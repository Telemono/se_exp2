# 学生成绩管理系统 · 需求规格说明

## 1. 用户角色

| 角色 | 说明 | 核心诉求 |
|------|------|----------|
| **管理员** | 系统的初始化和维护者 | 管理账号（增删改查用户）、重置密码、查看全量数据、备份与恢复数据文件 |
| **教师** | 任课与成绩录入者 | 维护自己课程下的学生名单、录入/修改/删除成绩、查看所教班级的统计信息 |
| **学生** | 成绩的查阅者 | 查询自己各门课程的成绩、查看个人统计（总分、平均分、排名） |

一个用户账号只能绑定一种角色，登录后按角色进入对应菜单。

## 2. 功能需求列表

### 2.1 公共功能
- **F1 登录**：输入用户名 + 密码，验证通过后进入对应角色菜单；连续失败 3 次锁定该账号本次会话。
- **F2 修改密码**：登录后可修改自己的密码，需二次确认新密码。
- **F3 退出登录 / 退出程序**：返回登录界面或结束程序。

### 2.2 管理员功能
- **F4 用户管理**：添加用户（用户名、初始密码、角色）、删除用户、重置用户密码、列出所有用户。
- **F5 课程管理**：创建课程（课程编号、课程名、学分、任课教师）、修改课程信息、删除无成绩记录的课程。
- **F6 选课管理**：把学生加入某课程、把学生移出某课程。
- **F7 数据备份与恢复**：将内存中的全部数据保存为 JSON 文件；从 JSON 文件重新加载。

### 2.3 教师功能
- **F8 查看授课名单**：列出自己任教课程及其选课学生。
- **F9 成绩录入**：为选课学生录入一门课的成绩（0–100 的数值）。
- **F10 成绩修改**：修改已录入的成绩，需确认操作。
- **F11 成绩删除**：删除某学生的该课程成绩，需确认操作。
- **F12 成绩统计**：查看所教课程的最高分、最低分、平均分、及格率、各分数段人数。

### 2.4 学生功能
- **F13 查询成绩**：查看自己所有课程的成绩及学分加权平均分（GPA 式计算）。
- **F14 查看排名**：查看自己在班级（按入学信息划分）内的总分排名，可选择是否公开显示。

### 2.5 持久化
- **F15 自动保存**：每次数据变更后立即写回 JSON 文件，程序崩溃不丢已确认的数据。

## 3. 非功能需求

- **N1 单文件可运行**：全部逻辑放在一个 `.py` 文件中，只用 Python 标准库（`json`、`os`、`getpass`、`hashlib` 等），`python main.py` 直接运行，无需安装任何第三方包。
- **N2 跨平台**：兼容 Windows / macOS / Linux 的终端环境，不使用平台特有 API。
- **N3 数据安全**：密码以 SHA-256 加盐哈希存储，绝不保存明文。
- **N4 数据持久化**：数据保存在程序目录下的 `data.json`，首次运行自动初始化（含一个默认管理员账号 admin/admin123，并在首次登录时强制改密）。
- **N5 响应速度**：数据量按教学场景规模设计（学生 ≤ 2000 人，课程 ≤ 100 门），所有操作应在 1 秒内完成，无需引入复杂数据结构优化。
- **N6 交互友好**：菜单式命令行界面，每个操作有明确提示；危险操作（删除、重置）要求二次确认。
- **N7 输入健壮**：对一切用户输入做合法性校验，非法输入给出提示并允许重试，绝不因异常输入导致程序崩溃。
- **N8 可维护性**：代码按「数据层 / 业务逻辑层 / 界面层」划分函数与注释，单文件内分区清晰。

## 4. 边界与异常

### 4.1 输入边界
- 用户名：4–20 位，字母数字下划线，不区分大小写地保证唯一。
- 密码：至少 6 位；新密码两次输入不一致时拒绝并提示重输。
- 成绩：仅接受 0–100 的整数或保留一位小数；空值表示「未录入」，不能当作 0 分参与统计。
- 学号/课程编号：系统内唯一，重复创建时拒绝并提示。

### 4.2 操作边界
- 教师只能操作**自己任教**的课程与成绩，越权访问其他课程时提示「无权操作」。
- 学生只能查看**自己**的成绩，无法访问他人数据。
- 删除用户前校验：教师名下有课程、学生名下有成绩时，禁止删除或要求先转移/清理。
- 删除课程前校验：该课程存在成绩记录时禁止删除。

### 4.3 异常场景
| 场景 | 处理 |
|------|------|
| `data.json` 不存在 | 自动初始化，创建默认管理员 |
| `data.json` 损坏 / JSON 解析失败 | 提示数据文件损坏，拒绝启动并备份损坏文件为 `data.json.bak`，退出前不覆盖原文件 |
| `data.json` 写入失败（磁盘满、权限不足） | 操作回滚到内存变更前状态，提示用户检查文件权限 |
| 登录连续失败 3 次 | 锁定账号，本次会话内拒绝再次尝试 |
| 中途强制退出（Ctrl+C） | 捕获 `KeyboardInterrupt`，把已确认的数据落盘后再退出 |
| 并发运行两个实例 | 不做锁机制（教学场景接受此限制），但在启动时检测并提示「数据文件可能被另一进程占用」 |

### 4.4 明确超出范围（本期不做）
- 图形界面、网络访问、多机同步。
- 教师代录、成绩申诉流程、历史成绩版本回溯。
- 大量数据（万级以上）的性能优化。
