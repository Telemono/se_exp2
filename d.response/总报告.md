## 1 项目概述

### 1.1 背景与目标

本项目以“学生成绩管理系统”为载体，完整走通软件工程的基本流程：需求分析、概要设计、详细设计、编码实现、测试与发布。目标是在明确的工程约束下，交付一个可运行、可演示、可维护的单文件命令行系统，并留下各阶段可追溯的文档。

### 1.2 技术约束

- 单文件 Python 脚本，`python student_grade_system.py` 直接运行；
- 不使用 Web 框架（Flask / Django / FastAPI 等）；
- 不使用数据库（MySQL / SQLite / MongoDB 等），改用本地 JSON 文件持久化；
- 仅依赖 Python 标准库；
- 命令行菜单式交互，面向小规模教学数据。

### 1.3 范围

实现登录鉴权、学生管理、课程管理、成绩录入/修改、成绩查询、课程统计、学生自助查询与 JSON 持久化。明确不做：图形/Web 界面、数据库、网络与并发、删除及级联、GPA/学分加权、导入导出、自动化测试与 CI（见 `b.response/deepseek.md` 第 5 节）。

## 4 实现概述

### 4.1 数据模型

内存中一个顶层字典 `data`，含四个数组，持久化为 `grades_data.json`：

| 键 | 元素结构 | 约束 |
|---|---|---|
| `users` | `{username, password, role, student_id}` | `role ∈ {admin, teacher, student}` |
| `students` | `{id, name, gender, class_name}` | `id` 唯一；`gender` 空则“未知”，`class_name` 空则“未分班” |
| `courses` | `{id, name}` | `id` 唯一 |
| `scores` | `{student_id, course_id, score}` | `(student_id, course_id)` 逻辑唯一；`score` 为 0–100 浮点 |

### 4.2 模块与关键函数

| 模块 | 关键函数 | 职责 |
|---|---|---|
| 入口主控 | `main` | 加载数据、登录、按角色分发菜单 |
| 认证与权限 | `login` / `find_user` | 三次机会校验，返回用户或失败 |
| 持久化 | `load_data` / `save_data` | JSON 读写、缺失键补齐、损坏回退 |
| 查找工具 | `find_student` / `find_course` / `find_user` | 线性查找，未命中返回 `None` |
| 学生管理 | `list_students` / `add_student` | 列表、新增（查重、非空校验） |
| 课程管理 | `list_courses` / `add_course` | 列表、新增（查重、非空校验） |
| 成绩管理 | `set_score` / `input_score` / `query_student_scores` / `list_scores` | 录入/覆盖、范围校验、查询与平均分 |
| 统计 | `course_stats` | 人数 / 平均 / 最高 / 最低（空集合不除零） |
| 学生自助 | `student_view_self` | 按绑定学号查询本人成绩与平均分 |
| 菜单交互 | `admin_menu` / `teacher_menu` / `student_menu` | 角色菜单循环 |

调用层次：`main → 认证/菜单 → 业务模块 → 查找/校验工具 → 持久化模块`。

## 7 已知局限

1. 密码明文存储与比较，无会话与锁定，仅演示用。
2. `save_data` 失败不回滚、不明确回报调用方，存在内存与磁盘不一致窗口（D02）。
3. 不支持多进程/多用户并发写入，无文件锁。
4. 无删除学生/课程/成绩功能，无级联清理。
5. 未处理 `KeyboardInterrupt`，中途退出不保证落盘。
6. UTF-8 BOM 数据文件会被判损坏并回退默认数据，且不备份原文件（D07）。
7. 学生菜单两项功能输出重复（D01）。
8. 无自动化测试与 CI，测试脚本为一次性采集工具。
